# 不具合の直しに共通する条件

この条件は、実行の担当が fix-root-cause で、報告された不具合を直した repository と報告を判定するためのもので、どのお題にも当てる。ケースに固有の条件は、この後ろに続く。条件は判断の型だけを書き、正しい直し方の中身は書かない。

重み3は利用者の原則の芯（資料が期待を決める、全経路が通る内側の一か所を直す、赤から始める、テストのために実装を曲げない）、重み2は直しの骨組み、重み1は細部である。担当が何も変えずに終えたときは、変更を読む条件はすべて FAIL とする。

### expected-from-docs

重み: 3

PASS：報告は、症状が不具合であることを、業務の資料の決まり（節か拒む理由の名前）を根拠に示している。報告者の言葉だけを根拠にしていない。

FAIL：資料を根拠に挙げずに不具合と決めている。または、資料に無い期待を足して直している。

### repro-at-innermost-layer

重み: 3

PASS：症状を再現するテストを、症状が現れる最も内側の層（業務の判断の誤りなら集約か値オブジェクトのテスト）に置き、公開の振る舞いで確かめている。テストのためだけの公開や差し替えの口を足していない。

FAIL：再現のテストが無い。または、外側の層（入口や手順）にだけ置いている。または、テストのために実装へ公開や口を足している。

### paths-traced

重み: 2

PASS：報告が、症状を起こす入力が通る呼び出しの経路を、報告された経路のほかの入口も含めて挙げ、選んだ一か所がそのすべてに通ることを示している。

FAIL：報告された経路だけを挙げている。または、経路を示していない。

### minimal-change

重み: 2

PASS：変更は、症状を直す一か所と、再現のテストと、寄せた複製の除去に限られる。症状に関係しない整形、改名、別の不具合の修正、要求の追加をしていない。関係しない不具合に気付いたなら、直さずに報告に挙げている。

FAIL：症状に関係しない変更がある。

### names-and-comments

重み: 1

PASS：足した具体エラー、テスト、コメントの名前と文言は業務の資料の語で、コメントは自分の責務だけを書き、使う側の都合や実装の事情の断り書きが無い。

FAIL：業務の語でない名前か、使う側の都合や実装の事情を書いたコメントがある。
